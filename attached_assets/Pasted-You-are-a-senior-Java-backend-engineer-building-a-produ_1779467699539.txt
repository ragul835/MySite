## 2. DATABASE SCHEMA

### PostgreSQL — All Tables

#### users
CREATE TABLE users (
    id              BIGSERIAL PRIMARY KEY,
    email           VARCHAR(255) UNIQUE NOT NULL,
    password        VARCHAR(255) NOT NULL,
    full_name       VARCHAR(255) NOT NULL,
    role            VARCHAR(50) NOT NULL DEFAULT 'ADMIN',
    is_active       BOOLEAN DEFAULT TRUE,
    created_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

#### contact_submissions
CREATE TABLE contact_submissions (
    id              BIGSERIAL PRIMARY KEY,
    name            VARCHAR(255) NOT NULL,
    email           VARCHAR(255) NOT NULL,
    company         VARCHAR(255),
    phone           VARCHAR(50),
    service         VARCHAR(255) NOT NULL,
    budget          VARCHAR(100),
    message         TEXT NOT NULL,
    status          VARCHAR(50) DEFAULT 'NEW',
    admin_notes     TEXT,
    created_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Status values: NEW, REVIEWED, IN_PROGRESS, RESPONDED, CLOSED

#### projects
CREATE TABLE projects (
    id              BIGSERIAL PRIMARY KEY,
    title           VARCHAR(255) NOT NULL,
    description     TEXT NOT NULL,
    category        VARCHAR(100) NOT NULL,
    technologies    TEXT[] NOT NULL,
    image_url       VARCHAR(500),
    live_url        VARCHAR(500),
    github_url      VARCHAR(500),
    is_featured     BOOLEAN DEFAULT FALSE,
    display_order   INT DEFAULT 0,
    is_active       BOOLEAN DEFAULT TRUE,
    created_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

#### services
CREATE TABLE services (
    id              BIGSERIAL PRIMARY KEY,
    title           VARCHAR(255) NOT NULL,
    description     TEXT NOT NULL,
    icon            VARCHAR(100) NOT NULL,
    features        TEXT[] NOT NULL,
    display_order   INT DEFAULT 0,
    is_active       BOOLEAN DEFAULT TRUE,
    created_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

### JPA Entity Mapping Rules
- Use @Entity, @Table annotations
- Use @Id with @GeneratedValue(strategy = GenerationType.IDENTITY)
- Use @Column for all fields with proper nullable, length constraints
- Use @CreationTimestamp and @UpdateTimestamp from Hibernate
- Use @Enumerated(EnumType.STRING) for enum fields
- Use Lombok @Data, @Builder, @NoArgsConstructor, @AllArgsConstructor
- Map PostgreSQL TEXT[] arrays with a custom converter or @ElementCollection

## 4. SPRING SECURITY CONFIGURATION

### SecurityConfig.java
@Configuration
@EnableWebSecurity
@EnableMethodSecurity
public class SecurityConfig {

    Configure:
    - CSRF disabled (stateless REST API)
    - Session management: STATELESS
    - CORS: allow frontend origins
    - Public endpoints:
        POST /api/v1/auth/login
        POST /api/v1/contact
        GET  /api/v1/projects/**
        GET  /api/v1/services/**
        GET  /swagger-ui/**, /v3/api-docs/**
    - All other endpoints: authenticated (JWT required)
    - Add JwtAuthenticationFilter before UsernamePasswordAuthenticationFilter
    - Use BCryptPasswordEncoder for password hashing
}

### JWT Configuration
- Secret key: loaded from environment variable JWT_SECRET
- Token expiry: 24 hours (configurable)
- Token format: Bearer <token>
- Claims: sub (user email), iat, exp, role
- JwtTokenProvider methods:
    - generateToken(UserDetails) → String
    - getUserEmailFromToken(String) → String
    - validateToken(String) → boolean

### JwtAuthenticationFilter
- Extends OncePerRequestFilter
- Extract token from Authorization header
- Validate token
- Set SecurityContext with authenticated user
- Skip for public endpoints

## 5. EMAIL NOTIFICATION SYSTEM

### When to Send Emails
1. New contact form submission → Notify agency admin
2. Contact status changed to RESPONDED → Optionally notify the client

### Email Template — New Contact Notification
Subject: "New Contact Submission — {name} | {service}"
To: configured admin email from environment variable

Body (HTML):
- Greeting
- Submission details: Name, Email, Company, Phone, Service, Budget, Message
- Direct link to admin panel to review
- Timestamp

### Configuration (application.yml)
spring:
  mail:
    host: ${MAIL_HOST:smtp.resend.com}
    port: ${MAIL_PORT:587}
    username: ${MAIL_USERNAME}
    password: ${MAIL_PASSWORD}
    properties:
      mail.smtp.auth: true
      mail.smtp.starttls.enable: true

agency:
  admin-email: ${ADMIN_EMAIL:admin@agency.com}
  frontend-url: ${FRONTEND_URL:http://localhost:3000}

### Implementation
- Create EmailService interface + EmailServiceImpl
- Use JavaMailSender to send emails
- Use Thymeleaf or simple HTML string templates
- Make email sending async with @Async to avoid blocking the API response
- Log email failures but do not fail the contact submission

## 7. SECURITY STANDARDS

Implement ALL of these:

1. **Password Hashing**: BCryptPasswordEncoder with strength 12
2. **Input Validation**: Jakarta Bean Validation on ALL DTOs
3. **SQL Injection Prevention**: Use parameterized queries via JPA (never raw SQL concatenation)
4. **CORS Protection**:
   - Allow origins: frontend URL only (configurable via env var)
   - Allow methods: GET, POST, PUT, PATCH, DELETE, OPTIONS
   - Allow headers: Authorization, Content-Type
   - Allow credentials: true
5. **Rate Limiting**: 
   - Contact form: 5 requests per IP per minute
   - Login: 10 attempts per IP per 15 minutes
   - Use Bucket4j or a custom filter with ConcurrentHashMap
6. **Environment Variables**: ALL secrets in env vars, never in code or committed files
7. **Request Size Limit**: Max 10MB request body
8. **Security Headers**: via Spring Security defaults + custom headers
9. **Logging**: Log all authentication attempts, contact submissions, and admin actions
   - Use SLF4J + Logback
   - Do NOT log passwords or tokens
